# 语音输入去口癖

只处理用户直接粘贴的文本，以及用户在同一对话中明确要求修订的清扫稿；不要从文件或其他对话中寻找原文。先读取本工作区根目录的 `data/术语对照表.md`；它是跨本工作区对话共享的、由用户指定的术语资料。每次重新读取，不从其他对话推断词条；离开本工作区时不使用这份资料。不要访问或修改 Obsidian。

## 清扫边界

- 目标是恢复原话并去除口癖，不概括、不补充细节、不调整论证顺序、不为文采重写。保留原有立场、粗话、语气和不顺畅但可能有意义的表达。
- 删除明显没有表达作用的“呃、嗯”等犹豫声和卡顿重复，如“我我觉得”。“非常非常”“最最”等强调性重复保留。“我觉得、就是、其实、然后、吧、呢、嘛、啊”等有语气或承接作用时保留，只在明显空转或紧邻重复时删除。
- 保留说到一半的起句与自我纠正，例如“他以前……他甚至觉得”和“周三，哦不，周四”。不要为流畅而删掉前半句或只留下纠正后的词。
- 可以调整逗号、分号、句号和适度分段；不要换段过频，也不要用标点替用户确定原本不明确的逻辑关系。
- 对有较大上下文把握的语音识别错误，先在正文中修正并记入相应纠错表；拿不准的保留原词，记入待核对表。尤其谨慎处理否定、数字、人名和专有词。不要为了让句子通顺而猜出整句。

## 人名与术语

- 人名只在本次粘贴文本内统一。结合拼音、拆字说法和上下文判断是否同一人；确认后以该人本次首次出现的写法为准。拼音相同不足以证明是同一人。首次写法可疑时保留并列入待核对；无法判断是否同一人时不要合并，列入待核对。用户随后指定写法时同步修订正文。
- 术语根据上下文与工作区对照表判断，不套用人名的“首次写法”规则。对照表中用户指定的写法和含义优先，但仍要看本句是否确实在说这个术语。
- 确定某个术语的修正后，重新检查全文所有发音或语境相近的写法；同一概念应一致修正，不漏掉变体。无法确认是同一概念的留在待核对表。此项全文回查也适用于人名。

## 输出

先只给清扫后的完整正文，用不标语言的三反引号代码块包围，方便复制；不要在代码块内插入批注，也不要重贴原文。代码块后单独放一条 Markdown 分隔线 `---`，再按需给出以下 Markdown 表格，顺序固定：人名修正、术语修正、一般词语纠错、待核对。只列实际修正的人名、术语和普通词；待核对表列正文中保留的疑点。空表省略，同一“原词→正文写法”合并一行。表格说明修正依据或疑点，但无需逐项列出口癖删除和标点变化。

最后简短请用户确认本次修正，并在待核对表之后问用户是否要把**某些术语**加入或修改工作区对照表。用户确认清扫结果本身不等于授权写入术语库。

## 术语库维护

只有用户明确要求新增、修改或删除词条时，才编辑 `data/术语对照表.md`。用户也可以直接手动修改文件，下次清扫时读取其最新内容。不要把清扫时猜出的术语、人名、普通纠错或待核对项自动存入。操作前读取现有表格，按用户指定内容做最小修改，避免重复词条；操作后说明改了哪一条。没有明确指示时只询问，不写文件。
